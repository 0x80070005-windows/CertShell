# CertShell
TUI-оболочка для работы с зашифрованными файлами CertGuard. Позволяет просматривать, добавлять, удалять и открывать зашифрованные файлы прямо из терминала — без необходимости каждый раз запускать отдельные утилиты.
Работает в связке с CertGuard — программой для шифрования файлов на базе AES-256-GCM.
Возможности

    📂 Навигация по зашифрованным файлам — перемещение по списку через Tab, выбор через Enter

    🔓 Автоматическая расшифровка и открытие — CertGuard вызывается сам, а после расшифровки файл открывается в нужной программе (mpv, eog, gedit)

    🔐 Двухфакторная аутентификация — логин/пароль + проверка сертификата на физическом носителе

    🗂️ Работа с директориями — переход между папками, добавление и удаление файлов

    🛠️ Мастер первого запуска — настраивает пути к сертификату и образу диска, создаёт учётные данные

    🖥️ Кроссплатформенность — поддержка Linux (и в планах Windows)

    🧩 Интеграция с CertGuard — использует общее ядро для работы с мастер-ключом

    ⚙️ Конфигурация через JSON — все пути хранятся в ~/.local/share/CertShell/config.json

Требования

    .NET 8.0 SDK или .NET 8.0 Runtime

    Linux (тестировалось на Arch Linux)

    CertGuard установлен и доступен в $PATH

    OpenSSL 1.1.1 или выше

    Следующие программы для открытия файлов:

        mpv — для видео

        eog — для изображений

        gedit — для текста

    gnome-terminal — для запуска CertGuard в отдельном окне

Установка зависимостей на Arch:
bash

sudo pacman -S dotnet-sdk mpv eog gedit openssl gnome-terminal

Установка
1. Клонирование
bash

git clone https://github.com/0x80070005-windows/CertShell.git

2. Сборка

4. Запуск

./out/CertShell

Создание сертификата OpenSSL

CertShell и CertGuard используют самоподписанный сертификат как «физический фактор» — файл, который лежит на флешке и без которого расшифровка невозможна. Сертификат нужно создать один раз, а затем носить на отдельном носителе.
Шаг 1: Создать приватный ключ и сертификат

Выполни в пустой папке (например, ~/cert_build/):
bash

mkdir -p ~/cert_build
cd ~/cert_build

openssl req -x509 -newkey rsa:4096 -sha256 -days 3650 -nodes \
    -keyout ca.key \
    -out ca.crt \
    -subj "/C=RU/ST=Omsk/L=Cherlack/O=CertShell_developer/OU=CertShell_developer/CN=Kirill/emailAddress=your@email.com"

Разбор параметров:
Параметр	Значение
-x509	создать самоподписанный сертификат
-newkey rsa:4096	новый ключ RSA на 4096 бит
-sha256	алгоритм подписи — SHA-256
-days 3650	срок действия — 10 лет
-nodes	не шифровать приватный ключ паролем
-keyout ca.key	файл с приватным ключом
-out ca.crt	файл с сертификатом
-subj	поля сертификата (замени на свои)
Шаг 2: Разместить сертификат на флешке

Скопируй только ca.crt на флешку:
bash

cp ~/cert_build/ca.crt /run/media/$USER/Ventoy/

Приватный ключ ca.key никуда копировать не надо — он тебе больше не понадобится. Можешь удалить его или сохранить в защищённом месте.
Шаг 3: Проверить содержимое
bash

openssl x509 -in /run/media/$USER/Ventoy/ca.crt -noout -subject -issuer -serial

Убедись, что поля Subject, Issuer и Serial Number соответствуют ожидаемым. CertShell сверяет их хеши с эталоном при каждом запуске.
Шаг 4: Резервная копия

Сохрани ca.crt в надёжном месте — если флешка потеряется или сертификат будет повреждён, без него расшифровать файлы невозможно. Лучше всего:

    Записать ca.crt на вторую флешку, которую хранишь отдельно

    Распечатать содержимое ca.crt (base64) на бумаге и убрать в сейф

    Не хранить копию на том же компьютере, где лежат .enc-файлы

Обновление сертификата

Если решишь пересоздать сертификат:

    Сгенерируй новый ca.crt

    Скопируй на флешку, заменив старый

    Удали файлы 1–4 в ~/.local/share/CertShell/:
    bash

    rm ~/.local/share/CertShell/{1,2,3,4}

    Запусти CertShell — он создаст новые хеши автоматически

⚠️ Все зашифрованные файлы станут недоступны, если ты пересоздал сертификат с другим Serial Number — потому что мастер-ключ в CertGuard привязан к конкретному сертификату. Пересоздавай сертификат только до начала шифрования файлов.
Первый запуск

При первом запуске CertShell запустит мастер настройки. Он:

    Напомнит команду создания сертификата OpenSSL и попросит убедиться, что сертификат уже лежит на флешке

    Спросит путь к папке с сертификатом — там, где лежит ca.crt

    Спросит путь к образу виртуального диска (.img)

    Запросит логин и пароль для входа в CertShell

    Сохранит всё в ~/.local/share/CertShell/config.json

text

Навигация в TUI

    Tab — переход к следующему элементу

    Enter — выбрать текущий элемент

    Ctrl+C — прервать и выйти из списка

Выбранный файл:

    если он заканчивается на .enc — вызывается CertGuard для расшифровки, после чего файл открывается в соответствующей программе

    если это обычный файл — открывается напрямую

Как это работает

    SetupWizard.Run() — если конфига нет, настраивает пути и учётные данные.

    CheckSecurity.Init() — проверка сертификата и логин.

    Основной цикл читает команды из stdin.

    Команда open запускает TUI-список:

        CertShell читает список файлов из /mnt/virtual_disk/

        Отображает их в терминале, пользователь выбирает через Tab/Enter

        Если выбранный файл заканчивается на .enc — вызывается CertGuard

        CertShell ждёт завершения CertGuard

        CertGuard расшифровывает файл во временную папку

        CertShell открывает расшифрованный файл в mpv/eog/gedit

Настройка sudo

Чтобы mount, umount, add, remove работали без запроса пароля каждый раз, добавь правило в sudoers:
bash

sudo visudo -f /etc/sudoers.d/certshell

Вставь (замени kirill на своё имя пользователя):
text

kirill ALL=(ALL) NOPASSWD: /usr/bin/mount, /usr/bin/umount, /usr/bin/cp, /usr/bin/rm, /usr/bin/fuser

Проверь пути:
bash

which mount umount cp rm fuser

Если что-то не в /usr/bin/ — поправь путь в sudoers.

⚠️ Не давай NOPASSWD на всё — только на конкретные команды. Иначе любой, кто получит доступ к твоей учётке, сможет делать что угодно от root.
Безопасность

CertShell использует многоуровневую защиту:
Уровень	Реализация
Аутентификация	Логин + пароль (SHA-512)
Проверка сертификата	Сверка хешей subject, issuer, serial, sigAlgo с эталоном
Физический фактор	Сертификат должен быть на флешке
Шифрование	AES-256-GCM + PBKDF2 (в CertGuard)
Привязка к устройству	Мастер-ключ разделён между флешкой и системным файлом
Блокировка экрана	Рекомендуется physlock на горячую клавишу
Рекомендации

    Не храните пароль в открытом виде. Используйте менеджер паролей.

    Не оставляйте расшифрованные файлы на диске — используйте exit после просмотра.

Известные ограничения

    Linux-only на данный момент. Поддержка Windows в планах.

    Зависимость от gnome-terminal для запуска CertGuard в отдельном окне. На других окружениях может не работать.

    Расшифрованный файл остаётся на диске пока открыт просмотрщик. Это неизбежно для любого решения, использующего внешние программы.

    Мастер-ключ привязан к сертификату — пересоздание сертификата делает старые .enc-файлы нечитаемыми.
    Храните резервную копию сертификата отдельно от системы.

    Проверяйте ~/.local/share/CertShell/config.json — если кто-то получил доступ к твоей домашней папке, он может подменить пути.
